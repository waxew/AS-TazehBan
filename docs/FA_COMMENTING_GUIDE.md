# استاندارد کامنت‌نویسی فارسی AS Team

این فایل قانون ثابت توسعه این پروژه است.

## قانون اصلی
- هر فایل سورس جدید یا هر فایل سورسی که ویرایش می‌شود باید توضیح فارسی واضح داشته باشد.
- در ابتدای فایل، هدف فایل، مسئولیت آن و ارتباطش با بخش‌های مهم پروژه توضیح داده شود.
- کلاس‌ها، Composableها، Widgetها، Screenها، Serviceها، Repositoryها، ViewModelها، Controllerها، DAOها و توابع مهم باید توضیح فارسی داشته باشند.
- منطق‌های غیر بدیهی، شرط‌های مهم، تبدیل داده، مدیریت State، Navigation، شبکه، دیتابیس، امنیت، مجوزها، Build و Release باید کنار کد توضیح داده شوند.
- کامنت باید «چرایی» و نقش کد را توضیح دهد؛ از کامنت‌های تکراری و بدیهی خودداری شود.
- TODO/FIXME باید فارسی و همراه با دلیل و کار موردنیاز باشد.
- هنگام تغییر منطق، کامنت مرتبط نیز باید هم‌زمان به‌روزرسانی شود.

## استثناها
فایل‌های تولیدشده خودکار، باینری، lock fileها، Vendor/Third-party و فایل‌هایی که نباید مستقیم ویرایش شوند از کامنت‌گذاری مصنوعی مستثنا هستند و در مستندات توضیح داده می‌شوند.

## روش اجرا
کامنت‌گذاری سورس upstream هم‌زمان با فارسی‌سازی و شخصی‌سازی همان فایل انجام می‌شود تا تاریخچه و Diffها تمیز و قابل پیگیری بمانند.

## هدف آموزشی
با خواندن سورس و کامنت‌ها باید مشخص باشد هر بخش چه می‌کند، چرا وجود دارد، به چه بخش‌هایی متصل است و برای تغییر آن از کجا باید شروع کرد.
